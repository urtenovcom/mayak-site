# Выкладка на прод

Состояние: **сайт на проде уже развёрнут**, API админки и база — **ещё нет**.
Ниже — как обновить сайт и как первый раз поставить админку.

Сервер: Ubuntu 22.04, приложение сайта в `/var/www/mayak`, запущено через pm2
(app `mayak`, порт 3000, `npm run start`), за nginx, SSL — Let's Encrypt,
ufw 22/80/443. Репозиторий приватный, поэтому `git clone` на сервере без токена
не работает — выкладка идёт архивом.

---

## 1. Обновление сайта

Локально:

```bash
git archive --format=tar.gz -o mayak.tar.gz HEAD
```

Скопировать на сервер (pscp/scp), распаковать в `/var/www/mayak` — распаковка не
трогает `node_modules` и `.env.local`. Затем на сервере:

```bash
npm ci && npm run build && pm2 restart mayak
```

`npm ci` нужен только если менялись зависимости. Сборку запускать детачно
(`setsid … > build.log`), статус смотреть по маркер-файлу, **не** через
`pgrep 'next build'` — он ложно матчит сам себя. На сервере должен быть swap
(RAM ~2 ГБ, иначе сборка падает по памяти).

### Что обязательно проверить после обновления

- `/robots.txt` и `/sitemap.xml` отдаются и содержат правильный домен.
- Форма заявки отправляется и заявка доходит (лог pm2: `[LEAD] {…}`).
- `/admin` отдаёт страницу входа, а не 500 (даже если API ещё не поднят).

## 2. Первая установка API админки

### 2.1. База

Поставить PostgreSQL 17 (пакетом или контейнером — как принято на сервере).
Завести базу и пользователя:

```sql
CREATE USER mayak WITH PASSWORD 'сгенерировать_стойкий_пароль';
CREATE DATABASE mayak OWNER mayak;
```

База наружу смотреть не должна: слушать только localhost, порт в ufw не открывать.

### 2.2. Код и окружение

**Важно:** `react-project-admin-back` — **отдельный git-репозиторий** внутри
рабочего каталога, и в основном репозитории он намеренно в `.gitignore`. Поэтому
`git archive` основного проекта его **не включает** — бэкенд выкладывается своим
архивом:

```bash
cd react-project-admin-back && git archive --format=tar.gz -o ../mayak-api.tar.gz HEAD
```

Если в бэкенде есть незакоммиченные правки, их сначала надо закоммитить в его
собственном репозитории — `git archive HEAD` берёт только зафиксированное.
Альтернатива (если историю вести не хотят) — упаковать каталог вручную, исключив
`node_modules`, `.worktrees`, `uploads`, `generated` и `.env`.

Распаковать в `/var/www/mayak-api`. Создать `.env`:

```env
NODE_ENV=production
PORT=5000
DATABASE_URL=postgresql://mayak:пароль@localhost:5432/mayak?schema=public
JWT_SECRET=сгенерировать_длинный_случайный
SITE_API_KEY=сгенерировать_длинный_случайный
```

`SITE_API_KEY` должен совпадать с `ADMIN_SITE_API_KEY` в `.env.local` сайта.

Шаблон запускает production только по HTTPS и требует `SSL_CERT_PATH` и
`SSL_KEY_PATH`. Есть два пути:

- **Рекомендуемый:** API слушает localhost по HTTP за nginx, который и держит
  TLS. Тогда запускать с `NODE_ENV=dev` (проверка среды в `server.js` завязана
  на HTTPS) либо снять это ограничение в коде — решение зафиксировать в
  `react-project-admin-back/README.md`.
- Отдать шаблону сертификаты Let's Encrypt напрямую через `SSL_*_PATH`.

Затем:

```bash
npm ci && npx prisma migrate deploy && npm run seed && pm2 start server.js --name mayak-api
```

`migrate deploy` (не `migrate dev`) — на проде миграции только применяются.
Сид идемпотентный: зальёт контент из снимка `prisma/seed-data.json` (каталог
сайта рядом для этого не нужен) и создаст администратора, если его ещё нет.
**Пароль администратора он печатает один раз — сохраните его сразу** и смените
после первого входа.

### 2.3. nginx

Поднять API на поддомене (например `api.mayak-modul.ru`) либо отдать его
локально по `proxy_pass http://127.0.0.1:5000`. Обязательные требования:

- **Затирать входящие `X-Forwarded-Host` и `X-Forwarded-Proto`** своими
  значениями — иначе ослабляется проверка происхождения серверных экшенов Next.
- `X-Forwarded-For` формировать из `$remote_addr`, а **не** через
  `$proxy_add_x_forwarded_for` — иначе клиент подставит любой IP и обойдёт
  ограничители частоты.
- Ограничить размер тела для загрузок (`client_max_body_size`) — на стороне API
  лимит 15 МБ.
- Каталог `/uploads` отдавать с `X-Content-Type-Options: nosniff`.

Сертификат — через certbot, автопродление уже настроено для основного домена.

### 2.4. Связать сайт с API

В `.env.local` сайта на сервере:

```env
ADMIN_API_URL=http://127.0.0.1:5000
ADMIN_SITE_API_KEY=тот_же_ключ_что_SITE_API_KEY
```

Перезапустить сайт: `pm2 restart mayak`.

### 2.5. Сразу после установки

1. Войти в `/admin`, **сменить пароль администратора** (сид его больше не
   перезапишет).
2. Отправить тестовую заявку с сайта и убедиться, что она появилась в панели.
3. Проверить, что API не доступен снаружи в обход nginx (порт 5000 закрыт ufw).

## 3. Включение уведомлений о заявках

Заявки уже пишутся в базу и в лог. Чтобы они приходили в мессенджер, нужны две
вещи в двух разных местах:

1. **Токен бота — в окружении сайта.** Добавить в `.env.local` и перезапустить
   `pm2 restart mayak`:

   ```env
   TELEGRAM_BOT_TOKEN=токен_от_BotFather
   ```

   В админке токена нет и быть не должно: это секрет, дающий полный доступ к
   боту, а база уезжает в резервные копии. Пока токен не задан, уведомления не
   уходят — на сохранение заявок это не влияет.

2. **Получатели — в админке**, Настройки → Настройка заявок. Это **список**:
   уведомление уходит каждому, до 20 получателей, у каждого свой `chat_id` и
   подпись «кто это». Получатели независимы — если один заблокировал бота,
   остальные всё равно получают заявку. Правка применяется без пересборки и
   перезапуска.

   `chat_id` вводится вручную либо подбирается кнопкой **«Узнать chat_id»**:
   она спрашивает у Telegram, из каких чатов боту недавно писали, и добавляет
   выбранный в список. Токен при этом остаётся на сервере, в браузер не
   попадает.

Переменная `TELEGRAM_CHAT_ID` в `.env.local` осталась **запасным вариантом**:
она срабатывает, только когда список в панели пуст (как и устаревшее одиночное
поле `leadTelegramChatId` в базе). Список из панели всегда в приоритете.

### Письмо о заявке

Устроено по тому же принципу: адрес получателя — в панели (то же место,
Настройки → Настройка заявок), доступ к почтовому ящику — в `.env.local`.

```env
SMTP_HOST=smtp.beget.com
SMTP_PORT=465
SMTP_USER=site@mayak-modul.ru
SMTP_PASSWORD=пароль_ящика
SMTP_FROM=Сайт «Маяк» <site@mayak-modul.ru>
LEAD_EMAIL=companymayak@mail.ru   # запасной получатель
```

Отправляем **не** с `companymayak@mail.ru`, а с отдельного ящика
`site@mayak-modul.ru`: домен `mayak-modul.ru` обслуживается почтой Beget
(MX `mx1.beget.com`), сервер — `smtp.beget.com`, порт 465, пароль — **обычный
пароль ящика**. Пароль внешнего приложения нужен только при отправке через
mail.ru, а mail.ru у нас лишь принимает письма.

Значения для прода возьмите из локального `.env.local` (в репозиторий он не
попадает). После правки `pm2 restart mayak`.

Порт 465 — SMTP поверх TLS; 587 работает через STARTTLS. `SMTP_FROM` менять обычно не нужно: почти все провайдеры отвергают
письмо, если `From` не совпадает с логином.

Пока пароль не задан, письма не уходят — заявка при этом всё равно попадает в
базу, в Telegram и в журнал.

**Зависший почтовый сервер ответ сайта больше не держит вовсе.** Письмо и
сообщение в Telegram отправляются уже ПОСЛЕ ответа пользователю (`after()` из
`next/server`), поэтому посетитель видит «Заявка отправлена» за десятки
миллисекунд независимо от того, отвечает ли SMTP. Практическое следствие для
эксплуатации: результат уведомлений появляется в логе pm2 отдельной строкой
`[LEAD] уведомления {…}` — она приходит на несколько секунд позже строки
`[LEAD] {…}` о самой заявке, и связаны они полем `receivedAt`.

### Счётчики аналитики

Яндекс.Метрика и Google Analytics 4 подключаются номерами из админки:
Настройки → Настройка метрик. Переменных окружения им не нужно, пересборка не
требуется. Пустое поле — счётчик не подключается; в `/admin` счётчиков нет
намеренно (раздел под noindex).

Полезно также задать `LEAD_LOG_FILE=/var/www/mayak/leads.jsonl` — это страховка
на случай, когда и база, и Telegram недоступны.

## 4. Резервные копии

```bash
docker exec mayak-postgres pg_dump -U mayak mayak > backup.sql
```

(на сервере без Docker — `pg_dump -U mayak mayak > backup.sql`)

Отдельно бэкапить каталог загрузок `uploads/` — файлы медиатеки в базе не лежат.
